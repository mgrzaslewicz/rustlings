The four operators

SyntaxMeansYou may…NOT the same as Java/Kotlin
T owned value move it, mutate it if mut, drop it at end of scope a Java local var never "owns" the heap object — GC does
&T shared / immutable borrow read; have unlimited others of these at once a plain Java reference can always be mutated through — &T can't
&mut T exclusive / mutable borrow read and write; only ONE may exist, and zero &T at the same time Java/Kotlin has no concept of an exclusive reference at all
*r dereference — "the value r points to" read or (if r: &mut T) write the pointee directly Java auto-dereferences everywhere; Rust makes it explicit with *

The one rule that governs & / &mut

Aliasing XOR mutability
At any point in the code, for a given value you may have either any number of &T or exactly one &mut T — never both at once.

Source: The Rust Book, ch4.2

When do you write *?

SituationExample
Mutating through a &mut*counter += 1;
Reading a non-Copy value out of a reference (rare, usually via a method instead)let n = *some_box;
Comparing a reference's pointee to a literalif *r == 5 { }
Most of the time — don't write itr.len() auto-derefs; no * needed

Lifetime syntax

WrittenRead as
&i32"a reference to an i32, lifetime inferred"
&'a i32"a reference to an i32, valid for at least 'a"
fn f<'a>(x: &'a str) -> &'a str"the returned reference lives at most as long as x"
struct S<'a> { part: &'a str }"an S can't outlive the string its part field borrows"

Key idea: a lifetime annotation never makes a value live longer. It's a claim you make that the compiler checks — "these two things are related, and the return value can't outlive its input(s)."

Source: The Rust Book, ch10.3

Glossary

Owner: the one variable responsible for dropping a value. Every value has exactly one at a time.

Move: transferring ownership. The old variable becomes invalid; the compiler enforces this at compile time (no runtime cost).

Borrow: creating a reference (& or &mut) to a value you don't own, for a limited scope.

Borrow checker: the compiler pass that enforces aliasing XOR mutability and that no reference outlives its owner.

Dangling reference: a reference to memory that's already been freed. Impossible to produce in safe Rust — the borrow checker rejects it at compile time.

Dereference: following a reference to reach the value it points to, spelled *r.

Lifetime: the span of code for which a reference is guaranteed valid. Written 'a. Not a runtime value — it's erased before the binary is built.
