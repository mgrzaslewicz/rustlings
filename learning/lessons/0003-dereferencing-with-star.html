Lesson 3 — the * operator

*: "the value this points to"

& creates a reference. * is its inverse: given a reference, it gets you back to the value it points to. Java and Kotlin never make you write this — every reference auto-dereferences everywhere (obj.method() just works). Rust auto-dereferences too, in most places — which is exactly why beginners get confused about when * is actually required.

Where you almost never need it

fn calculate_length(s: &String) -> usize {
    s.len()          // no * needed — method calls auto-deref
}

Calling a method or field access through a reference auto-dereferences, same as Java. This covers the large majority of your code — most rustlings exercises you've already solved with & alone never needed a *.

Where you do need it: mutating through &mut

The canonical case, straight from the Rust Book:

fn main() {
    let mut v = vec![100, 32, 57];
    for i in &mut v {
        *i += 50;
    }
}

i here has type &mut i32 — a mutable reference to one i32 inside the vector. i += 50 would try to add 50 to the reference itself, which isn't what you want and isn't even legal. *i += 50 dereferences first — "go to the i32 this points at, then add 50 to it." The Book calls this out directly: "we have to use the * dereference operator to get to the value in i before we can use the += operator."

The rule of thumb
Method calls and field access auto-deref for you. The moment you're using an operator directly on a reference — +=, ==, assignment — you usually need * to reach the pointee first.

Reading, not just writing

let x = 5;
let r = &x;

assert_eq!(5, *r);     // compare the pointee to 5
assert_eq!(5, r);      // ERROR: can't compare i32 to &i32 directly

r has type &i32, not i32. Comparing it directly to a plain 5 is a type mismatch — you have to dereference first to get an i32 on both sides.

Java / Kotlin

No dereference operator exists because you can't hold "the reference itself" as a distinct typed thing you operate on — obj and "what obj points to" aren't syntactically different.

Rust

r: &i32 and *r: i32 are genuinely different types. The type system forces you to say which one you mean.

Try it: rustlings

Open exercises/06_move_semantics/move_semantics5.rs. get_char there takes &String and calls methods on it with no * needed (auto-deref) — a good check that you can tell when * is and isn't required.

Check yourself

fn f(s: &String) -> usize { s.len() } — does this need a * before s.len()?

for i in &mut v { i += 1; } — does this compile as written?
